# Google GKE Cluster (XUI)

Adds four tabs to Kubernetes Cluster resources created or discovered by the Google Kubernetes Engine blueprint ([BP-g8g8aecx](../../blueprints/BP-g8g8aecx/)), and Connect and Workloads tabs to namespaces of the GKE Namespace blueprint ([BP-c9ca1i3z](../../blueprints/BP-c9ca1i3z/)). It is the GKE counterpart of the AWS EKS Cluster extension ([XUI-8a1jocmr](../XUI-8a1jocmr/)), and uses the Google Cloud console's labels.

- **Cluster**: status, mode, location type, release channel, and version support (standard, extended, or end of support, from GKE's upgrade information) in the header; the cluster basics (location, node zones, project, created, release channel, versions, total size, endpoints); Networking and Security cards; an Upgrades card with the control-plane versions the release channel offers, the auto-upgrade status and next targets, node pools behind the control plane, and an **Upgrade version** button; the cluster's features (load balancing, autoscaling, CSI drivers, NodeLocal DNSCache, Config Connector, Backup for GKE, Gateway API, logging and monitoring); the jobs running on the resource; and **Open in Google Cloud console**.
- **Node pools**: every node pool with status, Ready and total Kubernetes nodes, scale method and autoscaling range per zone, machine type, image type, version (tagged when behind the control plane), zones, Spot, and auto-upgrade and auto-repair; **Scale**, **Upgrade** (shown when the pool is behind the control plane), and **Delete** (hidden for the only pool) per row; **Add node pool** and **Refresh** in the toolbar. Below it, the Kubernetes nodes with status, node pool, version, OS image, zone, internal IP, and age.
- **Workloads**: nodes with Ready state, pressure conditions, CPU and memory requests against allocatable capacity, and pod counts; namespaces with pod, deployment, and service counts, each namespace landing zone linked to its CloudBolt resource with its owning group and tier; **Create namespace** in the toolbar.
- **Groups**: the CloudBolt groups entitled to the cluster's environment, which may order namespaces on the cluster, with their type. No groups shows **Unconstrained** (every group may order); only CloudBolt's Unassigned placeholder shows **Unassigned** (no group may order yet). **Add groups** in the toolbar, **Remove** per row (warning when it is the last group, which leaves the cluster unconstrained), and **Allow all groups**.
- **Connect** (namespace resources): the cluster, project, location, endpoint, authentication, Google Groups for RBAC, and network policy; the Google users, groups, and service accounts a RoleBinding in the namespace names, and the cluster admins; the GitHub Actions pipeline identities with a workflow to copy; the `gcloud container clusters get-credentials` and `kubectl` commands with copy buttons; and a kubeconfig to copy or download (it holds no secret). **Pipeline identity** and **Manage access** in the toolbar.
- **Workloads** (namespace resources): a read-only inventory: CloudBolt's quota as a row of meters (any other quota object in the namespace is listed below it), Deployments, StatefulSets and DaemonSets, pods, services and ingresses, persistent volume claims, and recent warning events. **Request quota change** in the toolbar. It never shows pod logs, Secrets, or ConfigMaps, and has no buttons that change the cluster.

Every button starts one of the blueprints' resource actions as a CloudBolt job (Upgrade GKE Version, Add GKE Node Pool, Scale GKE Node Pool, Upgrade GKE Node Pool, Delete GKE Node Pool, List GKE Node Pools, Create GKE Namespace, Manage GKE Cluster Groups, Manage GKE Namespace Access, Manage GKE Namespace Pipeline Identity, Request GKE Namespace Quota Change), so approvals, permissions, and job history apply. Scale opens a dialog prefilled from Google Cloud, and the Groups tab's buttons open dialogs that fill in the group change; the other buttons open CloudBolt's own dialog for the action. The tab is named Cluster rather than Overview because every resource already has an Overview tab.

## Prerequisites
- CloudBolt 8.6 or later.
- The `gcp_gke` shared module ([SHM-4yw92b8x](../../shared_modules/SHM-4yw92b8x/)) and, for the namespace tabs, the `gke_namespace` module ([SHM-kephq8iq](../../shared_modules/SHM-kephq8iq/)) synced to the same CloudBolt. Without them each panel shows an alert.
- Cluster resources that carry `gke_cluster_name`, `gke_project_id`, `gke_location`, and `env_id` or `gcp_rh_id` (stamped by the blueprint's build and discovery). Namespace resources that carry `gke_namespace_name`. The tabs only appear on those resources.
- The GCP handler of the cluster reads the cluster, its node pools, upgrade information, and the versions GKE offers in the cluster's location.
- The Workloads tabs and the Nodes table need the container orchestrator the blueprint registers (`container_orchestrator_id`), which holds the token of the `cloudbolt-admin` ServiceAccount the build creates. The extension verifies the API server against the cluster's own CA, so it works whether or not the cluster CA is in Admin > SSL Certificates.
- People who connect need the gcloud CLI with `gke-gcloud-auth-plugin`, a RoleBinding in the namespace (Manage access), and, for `get-credentials`, `container.clusters.get` on the project (Kubernetes Engine Cluster Viewer).

## Setup
1. Sync the repository, then restart the web server (`systemctl restart httpd` on the appliance): the extension adds URL paths, which CloudBolt loads only at startup, and Admin > Extensions flags it with the same reminder. Confirm the extension is enabled there. The restart also loads a changed shared module, which web processes cache.
2. Sync both blueprints as well, so their management actions exist: a button is hidden when its action is missing from the blueprint or the viewer may not run it. A blueprint sync resets the blueprint's group permissions to what the metadata lists, so restore them afterwards.

## Notes
- Viewing needs `resource.view` on the resource. Each button appears only when `resource_action_permitted` allows that action for the viewer, and the job runs as the viewer; an action that requires approval creates an order instead.
- Google Cloud is read with the cluster's handler and Kubernetes with the orchestrator's token, never with the viewer's identity, so every panel re-checks the viewer's CloudBolt permission and the namespace tabs stay read-only.
- GKE sizes node pools per zone, so the Scale dialog and the autoscaling range count nodes per zone.
- A node pool without a GKE Node Pool sub-resource is tagged "not synced"; **Refresh** (List GKE Node Pools) creates it.
- Panels load asynchronously and read Google Cloud and the cluster API on every load; nothing is cached in CloudBolt.
- Styling follows CloudBolt's own order and resource pages (theme tokens, Bootstrap 5, Bootstrap Icons) so Branded Themes apply.
