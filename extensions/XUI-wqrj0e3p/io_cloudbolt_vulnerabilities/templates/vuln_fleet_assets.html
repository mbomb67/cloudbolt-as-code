{% comment %} Script of the Vulnerabilities admin page. vuln_fleet.html includes this once. It draws the summary cards and three tables (vulnerabilities, the servers one vulnerability affects, servers) from JSON, one page of 25 at a time: the script never holds more than the page on screen, and every control change goes back to page 1 and asks the server again. Server values are placed with textContent and DOM methods only; no HTML string is ever built from them. The open view and vulnerability live in the URL hash: #view=servers, or #cve=. The resource tab (vuln_resource_tab.html) uses the same script. Everything it needs is opt-in per root element, so a root without these attributes behaves as the admin page always has: data-vuln-nohash="1" view and vulnerability are kept in memory; location.hash is never read or written (CloudBolt's own tabs keep their state in it), and the row links and the way back are buttons, not links. data-vuln-scan-url a "Scan all servers" button (data-vuln-act="scan-all", hidden until the summary says can_scan) posts here, and the summary's run object draws a banner into [data-vuln-run]; while a run is in progress a light request (summary?run=1) runs every 5 s and the summary and the open pane reload only when the run's progress changes or the run ends. When a run goes from absent to live (the button was just used) the visible pane is also reloaded once, quietly, on the next light poll, because the rows were fetched before the scans' jobs existed and must now read "Scanning". summary.servers_total > 0 with summary.servers = 0 (a resource whose servers are all unscanned) keeps the explanation and shows the Servers list instead of the cards, the view switch ([data-vuln-switch]) and the Vulnerabilities view. [data-vuln-patch-all] the "Install updates on all servers" link (resource mode only: the admin page has neither the link nor [data-vuln-patch-last]). It is a plain anchor that opens CloudBolt's own dialog (class open-dialog), so it has no data-vuln-act and this script never handles its click; it is un-hidden when the summary's patch says offer and no run is live, and its href is used only when it starts with "/". A run whose kind is "patch" is drawn as "Installing updates", with the server it is on and the run's message; a change of message alone redraws the banner without reloading the panes. [data-vuln-patch-last] shows the summary's patch_last, the result of the last update run, and is hidden while a run is live. The admin page alone opts in to the full Servers view with data-server-filters-url on the root (the resource tab has none, so it gets none of this): data-server-filters-url the filter choices (Group, OS build, Owner, Environment), fetched when the Servers view opens and again after a summary reload; with it the Servers table gets sortable headers (a button in each header, aria-sort on the th), the "Exploited only" and "With a fix only" boxes, an Owner and a "With a fix" column and, when the answer's bulk object says enabled, a checkbox column and the Install updates bar. data-servers-select-url "Select all N matching" (the answer's bulk.select_url is preferred). data-servers-patch-url the POST that starts one update run for the selected servers (the answer's bulk.run_url is preferred). data-csrf is sent as X-CSRFToken. Selection is a Map of server id to hostname in memory: it survives paging and sorting, and is cleared when the search or a filter changes, after a run starts, and by "Clear selection". It is never stored. The search, filters, sort and page are kept in sessionStorage (key vuln-fleet-servers, always inside try/catch) so the way back from a server tab restores them; nothing is stored with data-vuln-nohash. Installing is confirmed in an inline panel above the table, never in a browser dialog. While a row on the page says it is running, the pane refetches itself quietly every 15 seconds. A root is initialised once (data-vuln-init), at once when the document has already loaded (the tab HTML is injected after the page), and its timers stop when it leaves the document. {% endcomment %}
