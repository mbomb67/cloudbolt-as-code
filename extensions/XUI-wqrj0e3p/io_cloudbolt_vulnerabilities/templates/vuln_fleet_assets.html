{% comment %} Script of the Vulnerabilities admin page. vuln_fleet.html includes this once. It draws the summary cards and three tables (vulnerabilities, the servers one vulnerability affects, servers) from JSON, one page of 25 at a time: the script never holds more than the page on screen, and every control change goes back to page 1 and asks the server again. Server values are placed with textContent and DOM methods only; no HTML string is ever built from them. The open view and vulnerability live in the URL hash: #view=servers, or #cve=. The resource tab (vuln_resource_tab.html) uses the same script. Everything it needs is opt-in per root element, so a root without these attributes behaves as the admin page always has: data-vuln-nohash="1" view and vulnerability are kept in memory; location.hash is never read or written (CloudBolt's own tabs keep their state in it), and the row links and the way back are buttons, not links. data-vuln-scan-url a "Scan all servers" button (data-vuln-act="scan-all", hidden until the summary says can_scan) posts here, and the summary's run object draws a banner into [data-vuln-run]; while a run is in progress a light request (summary?run=1) runs every 5 s and the summary and the open pane reload only when the run's progress changes or the run ends. summary.servers_total > 0 with summary.servers = 0 (a resource whose servers are all unscanned) keeps the explanation and shows the Servers list instead of the cards, the view switch ([data-vuln-switch]) and the Vulnerabilities view. A root is initialised once (data-vuln-init), at once when the document has already loaded (the tab HTML is injected after the page), and its timers stop when it leaves the document. {% endcomment %}
