# Azure AKS Cluster (XUI)

Adds three tabs to Kubernetes Cluster resources created or discovered by the Azure Kubernetes Service blueprint ([BP-20q58q9z](../../blueprints/BP-20q58q9z/)), and Connect and Workloads tabs to namespaces of the AKS Namespace blueprint ([BP-dogqi827](../../blueprints/BP-dogqi827/)). It is the AKS counterpart of the AWS EKS Cluster extension ([XUI-8a1jocmr](../XUI-8a1jocmr/)), and uses the Azure portal's labels.

- **Cluster**: the portal's status (for example "Succeeded (Running)"), pricing tier, and Kubernetes version support (N to N-2 supported, N-3 platform support, older out of support) in the header; the Essentials (resource group, status, location, subscription, Kubernetes version, API server address, network configuration, node pools, pricing tier); Kubernetes, Networking, and Security property cards; an Upgrades card with the control-plane versions AKS offers, the automatic upgrade channel, node pools behind the control plane, and an **Upgrade version** button; the add-ons and cluster extensions installed; the jobs running on the resource; and **Open in Azure portal**.
- **Node pools**: every node pool with provisioning and power state, scale method, target and Ready nodes, autoscale range, mode, operating system, Kubernetes and node image version (with a New image tag when AKS has a newer one), node size, and zones; **Scale**, **Upgrade** (shown when the pool is behind the control plane or has a new image), and **Delete** (hidden for the only System pool) per row; **Add node pool** and **Refresh** in the toolbar. Below it, the Kubernetes nodes with status, node pool, versions, zone, internal IP, and age.
- **Workloads**: read through the cluster's container orchestrator: nodes with Ready state, pressure conditions, CPU and memory requests against allocatable capacity, and pod counts; namespaces with pod, deployment, and service counts, each namespace landing zone linked to its CloudBolt resource with its owning group and tier; **Create namespace** in the toolbar.
- **Connect** (namespace resources): the managed namespace's cluster, resource group, API server address, authentication, and network policy; the Microsoft Entra principals whose roles cover the namespace (object IDs with their type, display names are not looked up); the GitHub Actions pipeline identities with a workflow to copy; the `az aks namespace get-credentials` and `kubelogin` commands with copy buttons; and the kubeconfig to copy or download when it holds no secret. **Pipeline identity** and **Manage access** in the toolbar.
- **Workloads** (namespace resources): a read-only inventory read live through the cluster's orchestrator: quota usage as a row of meters covering the AKS-managed CPU and memory quota and CloudBolt's storage, claim, and pod quota, Deployments, StatefulSets and DaemonSets, pods, services and ingresses, persistent volume claims, and recent warning events. **Request quota change** in the toolbar. It never shows pod logs, Secrets, or ConfigMaps, and has no buttons that change the cluster.

Every button starts one of the blueprints' resource actions as a CloudBolt job (Upgrade AKS Version, Add AKS Node Pool, Scale AKS Node Pool, Upgrade AKS Node Pool, Delete AKS Node Pool, List AKS Node Pools, Create AKS Namespace, Manage AKS Namespace Access, Manage AKS Namespace Pipeline Identity, Request AKS Namespace Quota Change), so approvals, permissions, and job history apply. Scale opens a dialog prefilled from Azure; the other buttons open CloudBolt's own dialog for the action. The tab is named Cluster rather than Overview because every resource already has an Overview tab.

## Prerequisites
- CloudBolt 8.6 or later.
- The `azure_aks` shared module ([SHM-ptvp0km4](../../shared_modules/SHM-ptvp0km4/)) and, for the namespace tabs, the `aks_namespace` module ([SHM-cozv547n](../../shared_modules/SHM-cozv547n/)) synced to the same CloudBolt. Without them each panel shows an alert.
- Cluster resources that carry `aks_cluster_name`, `aks_resource_group`, and `env_id` or `azure_rh_id` (stamped by the blueprint's build and discovery). Namespace resources that carry `aks_namespace_name`. The tabs only appear on those resources.
- The service principal of the cluster's Azure handler reads the cluster, its upgrade profiles, node pools, and extensions, and the region's Kubernetes versions. The subscription name shows only when it may also read the subscription; otherwise the subscription ID is shown.
- The Workloads tabs and the Nodes table need the container orchestrator the blueprint registers (`container_orchestrator_id`), which signs in with the cluster's admin credential, so local accounts must stay enabled on the cluster.
- People who connect need Azure CLI 2.80.0 or later and kubelogin. Their access is two role assignments on the managed namespace: Azure Kubernetes Service Namespace User plus Azure Kubernetes Service RBAC Reader, Writer, or Admin ([managed namespaces](https://learn.microsoft.com/en-us/azure/aks/managed-namespaces#assign-role)).

## Setup
1. Sync the repository, then restart the web server (`systemctl restart httpd` on the appliance): the extension adds URL paths, which CloudBolt loads only at startup, and Admin > Extensions flags it with the same reminder. Confirm the extension is enabled there. The restart also loads a changed shared module, which web processes cache.
2. Sync both blueprints as well, so their management actions exist: a button is hidden when its action is missing from the blueprint or the viewer may not run it. A blueprint sync resets the blueprint's group permissions to what the metadata lists, so restore them afterwards.

## Notes
- Viewing needs `resource.view` on the resource. Each button appears only when `resource_action_permitted` allows that action for the viewer, and the job runs as the viewer; an action that requires approval creates an order instead.
- Azure is read with the cluster's handler and Kubernetes with the orchestrator's admin credential, never with the viewer's identity, so every panel re-checks the viewer's CloudBolt permission and the namespace tabs stay read-only.
- While an automatic upgrade channel is set, AKS upgrades the control plane and node pools together and refuses a control-plane-only upgrade; the Upgrades card says so.
- A node pool without an AKS Node Pool sub-resource is tagged "not synced"; **Refresh** (List AKS Node Pools) creates it.
- Panels load asynchronously and read Azure and the cluster API on every load; nothing is cached in CloudBolt.
- Styling follows CloudBolt's own order and resource pages (theme tokens, Bootstrap 5, Bootstrap Icons) so Branded Themes apply.
